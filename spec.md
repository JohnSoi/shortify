# Техническая спецификация: Сервис сокращения ссылок (Pet-Project)

## 1. Общее описание и цели проекта
Веб-приложение и REST API для сокращения длинных URL-адресов с поддержкой аналитики переходов, управления сроком жизни ссылок, защиты паролем, генерации QR-кодов и ролевой/тарифной моделью.

**Цель проекта:** Демонстрация навыков Fullstack-разработки (проектирование БД, высокопроизводительные редиректы с кешированием, асинхронная аналитика, аутентификация, работа с API-ключами, контейнеризация).

---

## 2. Технологический стек

### Backend
* **Язык:** Python 3.12+
* **Фреймворк:** FastAPI (асинхронный режим)
* **ORM и миграции:** SQLAlchemy 2.0 (async) + Alembic
* **Валидация:** Pydantic v2
* **База данных (основная):** PostgreSQL 16
* **Кеширование и Rate Limiting:** Redis 7
* **Геолокация:** `geoip2` + локальная база MaxMind GeoLite2-City
* **Генерация QR-кодов:** `segno` или `qrcode` (генерация в PNG/SVG на лету или с кешированием)
* **Безопасность:** `passlib[bcrypt]` (хеширование паролей и API-ключей), `PyJWT` (access/refresh токены)

### Frontend
* **Фреймворк:** Vue 3 (Composition API, `<script setup>`) + TypeScript
* **Сборщик:** Vite
* **Стейт-менеджмент:** Pinia
* **Маршрутизация:** Vue Router
* **UI и стилизация:** Tailwind CSS + Headless UI (или PrimeVue / Shadcn-vue)
* **Графики аналитики:** Chart.js (`vue-chartjs`) или ECharts
* **HTTP-клиент:** Axios (с интерцепторами для JWT)

### Инфраструктура
* **Контейнеризация:** Docker + Docker Compose
* **Reverse Proxy:** Nginx (маршрутизация `/api` на бэкенд, статики на фронтенд, проксирование коротких ссылок)

## 3. Роли, тарифы и лимиты (Эмуляция биллинга)

В системе предусмотрено 3 уровня доступа:

| Параметр / Функция | Гость (Без регистрации) | Free (Зарегистрированный) | Pro (Подписка) |
| :--- | :---: | :---: | :---: |
| Создание короткой ссылки | Да | Да | Да |
| История ссылок в ЛК | Нет | Да | Да |
| Лимит активных ссылок | Rate-limit по IP (5/час) | До 20 ссылок | Безлимит (до 10 000) |
| Кастомный алиас (`site.ru/my-link`) | Нет | Да (до 5 шт.) | Да (безлимит) |
| Срок жизни ссылки (TTL) | Фиксированный (7 дней) | Настраиваемый (до 30 дней) | Настраиваемый (бессрочно) |
| Защита ссылки паролем | Нет | Нет | Да |
| Генерация QR-кода | Базовый (Ч/Б) | Базовый (Ч/Б) | Кастомный (выбор цвета) |
| Аналитика переходов | Нет | Базовая (клики за 7 дней) | Полная (за все время, страны, города) |
| Доступ к REST API (API-ключи) | Нет | До 1 ключа (100 req/день) | До 5 ключей (10 000 req/день) |

*Реализация биллинга:* В личном кабинете есть страница «Тарифы». Нажатие кнопки «Перейти на Pro (Демо)» мгновенно меняет поле `plan` у пользователя в БД на `pro` и устанавливает `plan_expires_at = now() + 30 days`. Также доступна кнопка «Сбросить до Free» для удобного тестирования ограничений.

## 4. Архитектура базы данных (PostgreSQL)

### 4.1. Таблица `users`
* `id`: UUID (Primary Key)
* `email`: String (Unique, Index, Not Null)
* `username`: String (Unique, Not Null)
* `hashed_password`: String (Not Null)
* `plan`: Enum (`free`, `pro`) — default `free`
* `plan_expires_at`: DateTime (Nullable)
* `created_at`: DateTime (UTC)

### 4.2. Таблица `api_keys`
* `id`: UUID (Primary Key)
* `user_id`: UUID (Foreign Key -> `users.id`, Cascade Delete)
* `name`: String (название ключа, например, "My Script")
* `key_prefix`: String (первые 8 символов для отображения в UI, например `sk_live_a1b2...`)
* `hashed_key`: String (SHA-256 хеш полного ключа, Unique, Index)
* `is_active`: Boolean (default `True`)
* `last_used_at`: DateTime (Nullable)
* `created_at`: DateTime (UTC)

### 4.3. Таблица `links`
* `id`: UUID (Primary Key)
* `user_id`: UUID (Foreign Key -> `users.id`, Nullable — `NULL` для гостей)
* `original_url`: Text (Not Null)
* `short_code`: String(32) (Unique, Index, Not Null — генерируется алгоритмом Base62 или задается пользователем)
* `is_custom_alias`: Boolean (default `False`)
* `password_hash`: String (Nullable — если ссылка защищена паролем)
* `expires_at`: DateTime (Nullable — дата истечения срока жизни)
* `max_clicks`: Integer (Nullable — опциональный лимит переходов)
* `clicks_count`: Integer (default `0` — денормализованный счетчик для быстрого вывода)
* `is_active`: Boolean (default `True`)
* `created_at`: DateTime (UTC)

### 4.4. Таблица `click_events` (Аналитика)
* `id`: BigInteger (Primary Key, Autoincrement)
* `link_id`: UUID (Foreign Key -> `links.id`, Cascade Delete, Index)
* `clicked_at`: DateTime (UTC, Index)
* `ip_hash`: String(64) (хешированный IP для соблюдения приватности и подсчета уникальных кликов)
* `country`: String(100) (Nullable, из GeoLite2)
* `city`: String(100) (Nullable, из GeoLite2)
* `browser`: String(50) (Nullable, из User-Agent)
* `os`: String(50) (Nullable, из User-Agent)
* `device_type`: String(20) (`mobile`, `desktop`, `tablet`, `bot`)
* `referer`: Text (Nullable)

## 5. Ключевые бизнес-процессы и архитектура

### 5.1. Механизм быстрого редиректа (`GET /{short_code}`)
Редирект — самая нагруженная операция, она должна работать за миллисекунды:
1. При запросе `GET /{short_code}` приложение сначала ищет ключ `link:{short_code}` в **Redis**.
2. **Cache Hit:** Если данные найдены в Redis, проверяется срок жизни (`expires_at`) и наличие пароля (`has_password`).
   * Если ссылка защищена паролем — возвращается редирект на фронтенд-страницу ввода пароля (`/p/{short_code}`).
   * Если пароля нет — мгновенно отдается HTTP `302 Found` (или `307`) на `original_url`.
3. **Cache Miss:** Если в Redis пусто, делается запрос в PostgreSQL. Если ссылка валидна — результат записывается в Redis с TTL (например, 1 час), затем выполняется редирект. Если не найдена или истекла — `404 Not Found` / `410 Gone`.
4. **Асинхронный сбор аналитики:** Перед отдачей ответа клиенту задача сбора статистики добавляется в FastAPI `BackgroundTasks` (передаются `link_id`, `IP`, `User-Agent`, `Referer`).
   * В фоне происходит поиск страны и города по локальной базе `GeoLite2-City.mmdb`, парсинг `User-Agent`, запись строки в `click_events` и инкремент `clicks_count` в `links`.

### 5.2. Генерация коротких кодов
* Для автоматической генерации используется криптостойкий генератор случайных строк из алфавита **Base62** (`a-z`, `A-Z`, `0-9`) длиной 6–7 символов ($62^7 \approx 3.5$ триллиона комбинаций).
* Перед сохранением проверяется уникальность в БД (и отсутствие пересечений со системными роутами фронтенда: `/login`, `/dashboard`, `/api`, `/p` и т.д.).

### 5.3. Работа с API-ключами
* При создании ключа в ЛК генерируется строка формата `shrt_<32_random_chars>`.
* Пользователю полный ключ показывается **только один раз** в модальном окне.
* В базу сохраняется только SHA-256 хеш ключа.
* Внешние клиенты передают ключ в заголовке `X-API-Key: shrt_...`.

## 6. Спецификация REST API

### Аутентификация (`/api/v1/auth`)
* `POST /register` — регистрация (email, username, password).
* `POST /login` — вход, выдача `access_token` и `refresh_token`.
* `POST /refresh` — обновление токена.
* `GET /me` — получение профиля текущего пользователя и его текущего тарифа.

### Управление ссылками (`/api/v1/links`)
*(Поддерживает авторизацию как через `Bearer <JWT>`, так и через `X-API-Key`)*
* `POST /` — создание короткой ссылки (доступно и гостям без авторизации с учетом лимитов).
  * *Body:* `original_url`, `custom_alias` (opt), `expires_at` (opt), `password` (opt).
* `GET /` — список ссылок текущего пользователя (с пагинацией, поиском и фильтрацией).
* `GET /{id}` — детальная информация о ссылке.
* `PATCH /{id}` — редактирование ссылки (изменение `original_url`, `is_active`, `expires_at`, сброс/установка пароля). При изменении инвалидируется кеш в Redis.
* `DELETE /{id}` — удаление ссылки и очистка кеша в Redis.
* `GET /{id}/qr` — генерация и отдача QR-кода (query-параметры: `format=png|svg`, `color=#000000`).

### Публичный редирект и проверка пароля
* `GET /{short_code}` — основной эндпоинт редиректа (в корне домена).
* `POST /api/v1/public/verify-password/{short_code}` — проверка пароля для защищенной ссылки. При успехе возвращает `original_url` и записывает событие клика.

### Аналитика (`/api/v1/analytics`)
* `GET /overview` — общая сводка по аккаунту (всего ссылок, всего кликов за все время, кликов за сегодня).
* `GET /links/{id}` — подробная статистика по конкретной ссылке:
  * Query-параметры: `period=7d|30d|all`.
  * Ответ: массив кликов по дням (для графика), топ стран, топ городов, распределение по устройствам и браузерам.

### Профиль, API-ключи и Биллинг (`/api/v1/account`)
* `GET /api-keys` — список активных API-ключей пользователя (маскированных).
* `POST /api-keys` — выпуск нового API-ключа.
* `DELETE /api-keys/{id}` — отзыв ключа.
* `POST /subscription/upgrade` — эмуляция покупки Pro-подписки.
* `POST /subscription/downgrade` — откат на Free-тариф.

## 7. Структура страниц Frontend (Vue 3)

1. **Главная страница (`/`):**
   * Hero-блок с формой быстрого сокращения ссылки (работает для гостей и авторизованных).
   * Результат сокращения: готовая ссылка с кнопкой «Копировать», превью QR-кода и кнопкой скачивания.
   * Краткое описание возможностей и сравнение тарифов Free / Pro.
2. **Страница входа и регистрации (`/login`, `/register`):**
   * Формы с валидацией ошибок.
3. **Страница ввода пароля для ссылки (`/p/:shortCode`):**
   * Минималистичная страница, запрашивающая пароль для доступа к целевому URL.
4. **Личный кабинет — Мои ссылки (`/dashboard`):**
   * Карточки с общей статистикой.
   * Кнопка «Создать ссылку» (модальное окно с расширенными настройками: алиас, дата истечения, пароль).
   * Таблица/список ссылок с быстрыми действиями: копировать, QR-код, статистика, редактировать, удалить.
5. **Страница аналитики ссылки (`/dashboard/links/:id`):**
   * Линейный график переходов по дням.
   * Таблицы/чарты по странам и городам.
   * Круговая диаграмма по устройствам и браузерам.
6. **Настройки и API (`/dashboard/settings`):**
   * Управление API-ключами (генерация, копирование, удаление) + пример `curl`-запроса для документации.
   * Блок управления подпиской (текущий статус, эмуляция апгрейда до Pro).

  * Настройка базового CORS, структуры папок и конфигов (`pydantic-settings`).
* **Этап 2: Аутентификация и пользователи (2 дня)**
  * Реализация регистрации, логина (JWT), эндпоинта `/me`.
  * Реализация генерации и проверки `X-API-Key`.
  * Эмуляция переключения тарифов Free / Pro и dependency-проверок лимитов.
* **Этап 3: Ядро сокращателя и редиректы (2–3 дня)**
  * CRUD-операции для ссылок (генерация Base62, проверка кастомных алиасов).
  * Реализация кеширования в Redis и быстрого редиректа `GET /{short_code}`.
  * Поддержка паролей на ссылки и генерация QR-кодов.
* **Этап 4: Аналитика и GeoIP (2 дня)**
  * Интеграция базы MaxMind GeoLite2.
  * Реализация `BackgroundTasks` для записи кликов.
  * Написание агрегирующих SQL-запросов для графиков по дням, странам и городам.
* **Этап 5: Разработка Frontend на Vue 3 (3–4 дня)**
  * Верстка публичной главной страницы и формы сокращения для гостей.
  * Реализация авторизации и защиты роутов (`vue-router` guards).
  * Разработка дашборда ссылок, модальных окон QR-кодов и страницы графиков аналитики.
  * Разработка страницы настроек с управлением API-ключами и тарифом.
* **Этап 6: Полировка и документация (1–2 дня)**
  * Покрытие ключевых эндпоинтов тестами (`pytest` + `httpx`).
  * Оформление `README.md` со скриншотами, инструкцией по запуску в один клик и примерами API.
